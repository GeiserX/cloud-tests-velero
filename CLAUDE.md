# CLAUDE.md — cloud-tests-velero

## Overview
Terraform infrastructure and test scripts for evaluating Velero backup and disaster recovery across AWS EKS and GCP GKE. Academic dissertation project studying Recovery Time Objective (RTO) and Recovery Point Objective (RPO) in managed Kubernetes clusters.

## Tech Stack
- Terraform (HCL) — infrastructure provisioning
- Kubernetes (EKS, GKE)
- Velero (backup/restore)
- Shell scripts (test orchestration)
- R (data analysis)

## Development
```bash
# Deploy EKS infrastructure
cd eks/terraform && terraform init && terraform apply

# Deploy GKE infrastructure
cd gke/terraform && terraform init && terraform apply

# Run disaster recovery tests
cd eks && ./test.sh
```

## Architecture
- `eks/` — AWS EKS infrastructure and tests
  - `terraform/` — EKS cluster provisioning
  - `kubernetes/` — K8s manifests for test workloads
- `gke/` — GCP GKE infrastructure and tests
  - `terraform/` — GKE cluster provisioning
  - `kubernetes/` — K8s manifests for test workloads
- `R/` — Statistical analysis scripts for RTO/RPO data
- `docs/` — Documentation and images
- `Dissertation.pdf` — Full academic dissertation

## Key Rules
- Two disaster scenarios tested: software update failure and cloud zonal outage
- Always tear down cloud resources after testing to avoid costs
- Infrastructure is ephemeral — designed for test runs, not production
- R scripts expect timing data from `eks/timings.txt` format
